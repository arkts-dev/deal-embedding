# Deal UI generation surface

Use native write_file to create each missing file separately: deal and dealui. The host saves them as experience.deal and experience.dealui; the view imports the application as "./experience". Never overwrite existing files: use edit_sources with unique exact disjoint replacements against current source. read_file reads only these staged files; check_sources runs the full checker. Tool strings must decode to literal source quotes, backslashes, Unicode and whitespace; never put a file inside another file. Host owns revisions and filenames. No text envelopes, Markdown fences or copied boundary tokens.

DEAL and Deal UI have no ternary `condition ? a : b`, including inside action payloads. Compute dynamic input steps and selection values in DEAL state, then bind the scalar prop. For view alternatives use When/Else, not an inline conditional. Never use JavaScript expression syntax as a shortcut.

Imports first: the app module and this renderer's pack. Export `main(): null`, `export class State` with defaulted fields, `export function initialState(): State` returning `{}`, and `export class` for every view-visible action/row type. A non-exported State is not visible as app.State. Module and view filenames must match the imports.

Updates: a `// @ui-update` line immediately before `(state: State, action: Action): State`. Return a fresh complete state; never mutate the borrowed state or its collections; build arrays with explicit loops. Use a separate update function for each concrete exported action class. Do not invent an Action base/union or dispatch with `action is SomeAction`; DEAL has no such runtime type-test syntax. Every local variable requires an initializer at declaration, even if assigned later in branches: `let label: string = "";`, never `let label: string;`. Every loop variable is assigned at declaration: `for (let item: Item of state.items)`, never a bare or uninitialized declarator.

Effects: a `// @ui-effect` line immediately before `export async function run(state: State, action: RequestAction): CompletionAction`. The request update sets loading; the completion clears it and stores results. Catch failures and return an error completion so the UI recovers. Effects and updates may share the request action. No effect policies or failure mappers, and no effects from `main` or `initialState`.

Reusable checked presentation primitives: `import * as values from "ui/values";` in DEAL provides `decimal(value: int): string`, `clockMinutes(minutes: int): string` (0..1439, otherwise empty), and `inBounds(value: int, minimum: int, maximum: int): boolean`. Use these instead of generating digit/time loops; they infer no timezone, prices or suitability. For immutable updates use one typed fresh-outer copy helper for your State, then assign changed scalar fields; nested references remain borrowed and changed rows must be rebuilt. Keep async work in existing @ui-effect/update mechanisms and use existing Progress/Failure/onRetry components rather than inventing an async framework.

View expressions bind scalar state/row paths, literals and supported operators; they cannot call functions (for example `app.label(state)`). Compute derived labels in DEAL, store them in State/row fields, and bind those fields. Keyed row actions may capture checked row fields such as `id: row.id`; rebuild changed rows in the update, never mutate `state.rows[i]`.

Views: imports, then a `// @ui-root` line, then `export view Name(state: app.State): View { ui.Column() { ... } }`. Properties use a colon; components end without a semicolon. `ForEach(state.items, item: app.Item, key: item.id)` needs a stable key.

Capabilities: use only imports present in the catalog, await them, and read record fields explicitly. A required provider result must come from that provider, even if the catalogue describes its formula or example behavior. Never implement a local imitation or initialize a successful constant as a substitute. Keep provider-dependent outputs pending until an explicit user-triggered read succeeds. Follow their described argument formats and prerequisite reads. Resolve provider IDs from returned catalogue records; never send user prose as IDs or invent IDs. Unknown stock/price is pending, not zero or success. Validate availability and specification before calling an option suitable. Keep user requirements/budget editable and distinguish a local recomputation from a fresh provider read. Never use JavaScript collection methods (`map`, `filter`, `push`), `any` or `unknown`. Never concatenate an int into a string; show it with `IntText` or `Time`.

Requested outcomes are not just validation labels. When the task asks for a feasible allocation/selection with totals, category minimums or other constraints, compute an initial satisfying choice from the actual returned records after explicit loading, then let the user edit it. Check all supplied constraints together; do not leave all quantities at zero and require the user to solve the requested task. If no solution exists, show a real infeasibility result with the failed constraints; never invent data. If the task explicitly asks for manual selection only, preserve that behavior. This logic belongs in generated DEAL, never the renderer.

The supplied pack is the complete vocabulary. Use only declared components and properties; Row is adaptive, not a fixed horizontal layout. No image or arbitrary style. A component that declares an event with a payload must have an action consuming that payload. For Toggle, `value` is a string identity, NOT the boolean state; `checked` is the boolean state. The onChange string payload is that identity, not "on"/"off": return a fresh state with the selected boolean inverted. Example: `ui.Toggle(value: "follow-up", text: "Flag for follow-up", checked: state.followUp, onChange: action app.ToggleFollowUp { value: payload })`.

Reads and preparation only. Never write, never confirm, and never report that something is booked or approved. Native permission and confirmation surfaces stay outside generated UI.

If a requested capability is unavailable, explain that in the UI instead of inventing an import.

## Exact view syntax example

The pack import is literally `./platform.dealui-pack`, never `ui`, `platform/ui` or `std/ui`. Replace the app module filename with the supplied host filename. View conditionals use capitalized `When(...) { ... } Else { ... }`, never `if`, `If`, JavaScript templates or JSX. Event payload is the bare identifier `payload`, never `$value`, `value` or an empty action when a payload is declared.

```dealui
import * as app from "./experience";
import * as ui from "./platform.dealui-pack";
// @ui-root
export view Workspace(state: app.State): View {
    ui.Column() {
        When(state.loading) { ui.Progress(label: "Loading") } Else {
            ui.Button(text: "Load options", accessibilityLabel: "Load options", onClick: action app.Load {})
            ForEach(state.rows, row: app.Row, key: row.id) {
                ui.Option(value: row.id, title: row.title, detail: row.detail, price: row.price, meta: row.meta, enabled: row.available, selected: row.selected, accessibilityLabel: row.title, onSelect: action app.Pick { value: payload })
            }
        }
    }
}
```

Wire names may be DEAL keywords. Keep contract argument order and exact wire keys. For keyword-named table fields, use a string index with an explicit target type: `let periodStart: string = record["from"];`. Use ordinary application field names such as `periodStart`; keyword member access such as `record.from` is invalid. Read only fields declared by the actual capability contract. Application fields and local names must not be keywords such as `from` or `until`; use `periodStart`, `periodEnd` or `windowLabel`. For table results, declare intermediate typed locals: `let records: table[] = await catalogue.equipment(state.periodStart, state.periodEnd);` then `for (let record: table of records) { let cents: int = record.cents; }`. Set derived booleans such as `empty` in DEAL when needed by a view. An update must build and return a fresh complete state; do not mutate a helper-returned shallow copy that still aliases borrowed collections.

Input controls support `enabled`, `supporting` and `error`; IntField additionally supports a positive integer `step` and `format` (default `integer`; `euro-cents` displays a cents-valued integer as euros without changing its integer event payload). Always set numeric minimum and maximum explicitly to cover supplied initial values and useful edits; IntField's default maximum 999 is insufficient for most euro-cent budgets and minute-of-day values. Label currency inputs Total budget (€), use format: "euro-cents" and step 100; do not ask users to reason in cents. Derived currency outputs must also display euros with two decimal digits and a currency symbol or label, never raw cents (175000 cents is €1750.00). In DEAL source strings write the literal Unicode character `€` (or `EUR`), never a JSON-style `\u20ac` escape: DEAL does not support Unicode escape sequences. Decoded tool source must contain the actual character; do not put a second escaped source representation inside it. Prefer Money(label, minorUnits, currency) for output amounts; its backend formats explicit integer minor units with the currency's decimal precision. DEAL computes all amounts and Comparison status. Metric takes explicit value text and a separate unit, not an invented format property. Legacy Text may use a formatted output string prepared in DEAL; a safe currency string uses literal "EUR " plus integer-to-text formatting. DEAL has no implicit int-to-string conversion: use values.decimal(value) from ui/values, not JavaScript String/toString, raw int concatenation or generated digit loops. Before writing source, check currency characters are literal, not backslash-u text. SearchField uses the same string onChange payload as TextField. Button supports enabled. Validation and input-derived availability remain in DEAL. Do not read provider data merely to edit an input. Represent absence of selected id with an empty string when convenient; narrowing of nullable state properties is not assumed. Prefer a local non-null boolean/id plus explicit loops to nullable selected-row helpers. View collection length is not supported: derive an empty/count scalar in DEAL. Keep source compact and use std/string primitives rather than generating substring/contains helpers. Include required input and event plumbing, but no unused optional events.

## Task-facing presentation

The ordinary screen is the tool, not an explanation of the tool. Native Inspect owns provenance, model routing, captured facts, exact failures and technical evidence. Native consent owns disclosure and authority. Do not repeat them as paragraphs, safety banners, event-note transcripts or claims about actions not taken. Keep material task constraints visible next to the relevant control; never hide a real risk or confirmation requirement.

Start with usable controls and the result. The shell supplies the event/task heading; avoid repeating it or adding an expandable Section just to wrap the whole view. Prefer a flat Column with a small bounded group only when needed. Use short input labels with units and at most one brief assumption label for the group, not duplicated supporting text on every field. A simple editable comparison needs inputs and a prominent computed difference, not a walkthrough, formula explanation and concluding paragraph. Preserve exact quantities and behavior; remove redundant copy, not evidence or constraints. Keep the primary interaction and result visible together in a normal phone viewport. Use native pack defaults and its spacing/typographic hierarchy, without decorative heroes or nested cards.

Use concise task language and native controls: equipment, quantity, budget, options and review. Do not show module paths, compiler/error codes, source authorship, templates, workspaces, generation routes or technology badges in the application view. The native shell supplies navigation and task title; avoid repeating it in a large hero. Keep specification, quantity, friendly local period and total price visible where useful. Do not render duplicate UTC/raw timestamps, timezone identifiers, years on every row, repair explanations or overlapping headings; exact instants remain in state and capability arguments, visible in native Inspect. Use one Progress per pending operation, not both Spinner and Progress. Keep the initiating control near useful results instead of making users traverse repeated cards to act. Native Inspect exposes engineering information separately.

While an effect is pending, retain entered values, show Progress and disable the initiating Button and conflicting inputs/selection with enabled: !state.loading. Completion and error updates clear loading so controls become available again. Never simulate progress or data. No reads from init; only explicit user actions read provider stock. Catch errors into short actionable messages, including sharing instructions for permission denial, without displaying raw error.code/error.message. Raw failures are observed by the host logger. Use distinct validation, empty and retry states; no fake successful defaults. Preparing a descriptor is local review only: say Not booked, never booked, approved or secured.
