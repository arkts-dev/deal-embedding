# Maintained fragment composition

Use submit_compact with `{title,fragments,commands,display}`. Each fragment has a unique identifier matching [A-Za-z][A-Za-z0-9_]* (no hyphens), kind and closed config. The maintained fragment owns state, handlers, views, validation and lifecycle. Do not author a state/action/node graph. Configure any number of instances; display lists visible instance IDs in order. Commands have id, label and target IDs, not model-written execution steps; dependency execution is derived. Attach each provider resource to one command; do not add separate load/refresh commands for the same resource. The same command is its explicit refresh. Independent commands remain independent. Pure local compositions use commands:[]; never add a providerless command. Reads occur only on explicit action, never during generation or mounting. No selector/verifier call.

Formula fields are `{expr:"..."}`. References spell the ACTUAL fragment ID then its published port: if an input's id is amount, use amount.value; if a read's id is resource, use resource.result or resource.result.field. The words instance and port are placeholders, NOT literal prefixes. Bare fragment IDs are not values. An alternatives fragment publishes baskets (not result); a quotes fragment publishes results (plural). Quote-reply expressions use reply.field, never row.field; basket value arguments use item.field. Pure literals, parentheses, arithmetic + - * /, comparisons === !== < <= > >=, && || ! and floor/ceil/abs/choose/clock/integer/concat/length/sum/filter/any/all/project. Collection bodies use row.field. No assignment, source, arbitrary calls or provider invocation. Types and optional-field presence come from disclosed contracts. Missing ports, incompatible types and dependency cycles are rejected, never guessed. Literal strings use double quotes. HH:mm is clock(minuteOfDay). Never emulate a provider formula or freeze editable input into a request literal.

- input: label, format (integer/money/time/text/boolean), value and numeric minimum/maximum (zero placeholders for text/boolean). Money uses integral minor units: if task facts already specify cents/minor units, use them unchanged, never multiply them by 100. Numeric minimum <= initial value <= maximum is required. Time requires 0 <= minimum <= value <= maximum <= 1439 (1440 is invalid). Publishes value.
- read: disclosed binding {module,function} and formula arguments in exact parameter order. Publishes result and present. Result fields retain the actual disclosed schema, including nested/optional fields.
- result: label, format (money/time/number/integer/text), value formula. Publishes value and present. A dependent result is shown only while its input ports are present.
- comparison: limit and actual formulas, label. Editable inputs are separate input fragments. Publishes signed difference and present; displays magnitude and over/under/equal.
- choice: source array, identity/label/eligible/cost formulas over row. Selects the lowest-cost eligible option initially; keeps every option selectable with current validity. Publishes selected {id,label,eligible,cost} and present. IDs come from records.
- allocation: source, identity/label/cost/eligible formulas over row; total/budget/surcharge formulas; quotas [{label,minimum,predicate}]. Additive quotas may overlap. Allocates whole quantities without a fixed row/quantity ceiling; quantities, budget and choices stay editable. Publishes rows, total, valid and present. present means all referenced inputs/options are current; valid additionally checks allocation feasibility. Load source and prerequisite choices in the same command closure for one-action preparation. Failure cannot retain Ready.
- alternatives: source catalogue, identity/label/stock formulas; components {source,identity,quantity}: source is the current catalogue row's component array (e.g. row.parts or row.components), NOT the full catalogue; identity/quantity use row for each component record; roles [{label,quantity,predicate}] over actual disclosed records. Roles describe required physical units, not package/separate alternatives. Distinct roles consume distinct units even if predicates overlap. One-level bundles resolve identities against the same catalogue; shared component stock is aggregated. Publishes stock-qualified baskets with items/key/label; no fixed two-role signature or literal attributes path. All role predicates must include the task's material constraints. Preserve disclosed enum/value vocabulary; do not abbreviate connector/attribute values or invent unprovided spellings.
- quotes: source baskets, disclosed binding, ordered arguments. Arguments are {kind:"value",value:formula} or {kind:"basket",encoding:"idQuantity"|"records",idField,quantityField}. Preserve offset-bearing period instants as text inputs or exact constants; never turn them into local clock-only values or append Z to unchanged local time. Value arguments may read item fields; basket arguments encode actual selected IDs/quantities in the disclosed parameter type. cost/deposit/available/ttlMillis formulas read reply fields; budget is a current input formula. Whole-basket provider prices/deposits are authoritative. Replies retain their own conservative receipt expiry, not batch completion time; SessionClock invalidates age trust on suspend/reopen/backward signals. Refresh is explicit. Publishes results; displays current authoritative offers, including over-budget costs, with hire and refundable deposits separate.

Nested configs, arguments, roles and quotas are actual arrays/objects, never JSON-encoded strings. Derive requirements/initial values from authorized task facts, not expected test answers; provider records own IDs, eligibility, stock and prices. Missing matches, infeasibility and operational failure are not interchangeable.

submit_custom remains a separately measured typed custom-section slow path for genuinely uncovered behavior; source_fallback is the explicit full-source last resort. Neither substitutes for maintained coverage. Materialization happens once atomically. Afterwards exact decoded canonical source is the sole authority: read_file/edit_sources/check_sources only. Do not reassemble or overwrite. Every rejection, fallback, custom character and exact repair remains charged; rejected composition leaves the workspace unchanged.
