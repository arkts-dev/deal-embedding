# Composition

The native shell supplies navigation and task heading. Start with usable controls and computed results, not introductions, repeated headings, safety banners or captured-note transcripts. Inspect owns provenance, routing and engineering diagnostics; native consent owns disclosure/authority. Preserve material constraints beside relevant controls. Use short task language, units and one local-assumption label where needed.

Column sets reading order. Row groups related controls/values into equal-width columns that wrap at narrow widths or larger text; minimumChildWidth is a minimum logical width, not a fixed layout. Keep controls and their results close. Heading names a needed group; Text carries task content; Caption carries short supporting constraints. Use one PrimaryAction and subordinate SecondaryAction; Button remains supported. Payload-bearing events must consume payload.

Use native theme/spacing defaults. Avoid decorative heroes, nested cards and a Section wrapping the whole screen. Card is for a bounded group, not every row or spacing. Keep the main result and editable inputs visible together in a normal phone viewport; put long catalogues/secondary detail later. Do not truncate essential values, rely on color alone, or repeat the same amount in multiple summaries. Show friendly local periods/specifications where useful, not duplicate raw UTC timestamps, timezone identifiers, source paths or repair explanations.

Money(label, minorUnits, currency) formats integral currency minor units with ISO 4217 precision and device locale; EUR unless facts specify otherwise. Keep hire, refundable deposit and delivered totals distinct. IntField format euro-cents displays cents-valued state as euros; explicit bounds/step must cover useful edits. Never parse formatted currency back into state.

Metric(label, value, unit) uses text computed in DEAL. Comparison(status) accepts only Money or Metric children, including through When/ForEach/views. The backend never calculates a winner: DEAL supplies over/under/equal, feasibility and selection conclusions. Show magnitude separately; preserve requested alternatives. Use checked ui/values helpers for decimal/clock presentation.

DEAL owns constraints, validation, quantities, totals and suitability. Retain entered values during pending work; one Progress, disabled conflicting controls, honest empty/error/retry states. Provider reads require explicit actions, never initialization/mount. Recompute dependent conclusions after edits/selections; invalidate stale provider results. Prefill requested solutions from real records rather than asking users to type IDs or wire formats. Screens are task tools, not framework/test explanations; preparation is not booking or approval.
