# Android/JavaScript protocol

`embedding.d.deal` and `catalogue-policy.d.deal` are the public signatures. `ProtocolController` bootstraps a trusted compiled DEAL consumer; `Embedding` supplies Android mechanisms. `ApplicationProtocol` links application lifecycle and renderer inputs to the compiled application consumer; it does not provide an alternate native lifecycle. Compiler-derived `protocol-contracts.js` preserves nominal record identity. Generated UI has neither this declaration inventory nor these bindings. Only trusted orchestration/app policy may import them.

Generation, bounded repair and fallback execute in `core/generation.deal`. App build links its own policy asset directory; absent policy offers no catalogue. Policy `offer`/`lower` executes compiled DEAL in the preparation isolate, which cannot invoke application providers. Native code implements generic answer validation, checking, execution, authenticated transport, persistence and observation.

## Context and handles

Contexts copy and validate schema/value. Six kinds only; closed records support omitted optional fields. Strings count UTF-16 units. Maximum length/count is 0–8192, schema depth at most 8, record fields at most 32, and encoded context at most 8192 UTF-8 bytes. Empty records are legal. Duplicate fields, cycles, unknown kinds, incorrect element/field metadata and nonfinite or inverted number bounds reject, including in absent optional branches. Accessors return independent schemas. JSON is normalized at snapshot; values must consume the full input. No generic domain schema is implied.

IDs must have been issued or reconstituted by the same instance; copied metadata grants nothing. Requests are single-use, freeze context/contracts and retain their trace until shutdown. Cancellation is checked before inference, after each host operation and atomically before accepting prepared source. It stops waiting/acceptance, not remote compute/cost. Context/request resources live until shutdown.

## Source → Experience → Session

`generate` and `load` prepare checked source without mounting or saving. `run` mounts and commits source before returning a session; repeated live runs return that session. There is one live session per experience. Mount/save failure retains the preparation for explicit retry/release. Close retains source; cold run checks stored source against current contracts without inference. `saved` reissues retained identities; supplied metadata never changes stored title/origin/attempts. Release removes unused preparation, not saved source. Forget closes/deletes; failed persistence reports failure. Invalid or closed handles fail rather than silently minting resources. Embedding starts automatic progress at run and drives effects, replies and deadlines without observation calls. Only next returns snapshots: empty cursor reads current state, issued session cursors read a later change or wait, and faults participate in updates. Updates may coalesce; atomic read/register avoids lost wakeups. Invalid/foreign cursors raise DEAL Error. Dispatch returns null after action processing, not effect completion. Close/shutdown stop progress and reject outstanding next waits. Published synchronously records renderer acceptance, not pixel presentation; it never gates progress. Native bootstrap must execute blocking async mechanisms off the UI thread. Cancellation and observation do not queue behind awaiting model inference.

## Permissions

Grant/revoke synchronously change authoritative state inside the trusted controller isolate. Native admissions query that state before invoking a provider; there is no deferred grant notification or second native grant set. Pending remote operations retain their permission epoch, so revoke/regrant cannot resurrect an earlier reply. Provider authentication, authorization, consent, argument/result validation and deadlines remain independently enforced. Completed work cannot be undone.

## Policy

Available offers have 1–32 unique named questions; each has 1–255 unique described options and nonempty bounded instructions. Generic validation checks complete question coverage, selected issued options, finite probabilities/confidence and optional probability coverage/sum with rounding tolerance. Typed answers/confidence are not correctness or authority. App lowering validates domain relations; null source means unsupported fallback with a safe reason. Rejected deterministic source falls through to source generation. Classified model/provider transport failures retry without being recast as source errors. Generation recovers until acceptance or cancellation with no attempt or repetition ceiling; only eligible application-source diagnostics and explicit trusted runtime-test feedback enter source repair. The source pair remains digest-bound and every edit must match a unique disjoint original region. No full-rewrite repair strategy or fallback exists. Invalid initial envelopes trigger another initial-admission call within the same request; no invalid pair is executed or treated as a patch base. Failed patches keep the previous valid base and diagnostic windows. Optional trusted candidate tests run real sessions and feed failures back into exact patching before admission.

## Observation

Empty trace selects all; empty cursor starts a retained snapshot. Page limit 1–200; continuation is instance-local, single-use, bounded to 16 cursors and invalidated by clear. Appends do not disturb continuation. Events are chronological, wall time/elapsed are decimal millisecond strings, duration is nonnegative, and produced versus published versions remain distinct. Experience and session references are separate. Artifacts are captured/truncated/unavailable, with digests of stored bytes. Capture is private, explicit, bounded and nonretroactive. Eviction and incomplete health are not success evidence. Observation admission cannot replace an app result; clear removes observation only.

Native JSON records are mechanism transport. `public-protocol.js` owns validated context/request state and synchronous public operations inside the trusted consumer isolate; it never pre-injects individual call results. Async declarations return operations serviced by nonblocking native lanes. Cancellation rejects waiting/acceptance even when a mechanism remains computing. Native mechanisms independently check their resource references. Bootstrap reconstructs saved source metadata before exposing synchronous `saved()`. Production Organizer and Calendar use the compiled application consumer; the assertion-bearing consumer is a separate fixture. Embedding owns both progress and renderer-observation wiring, while applications own display and lifecycle choices. Android/JS is the supported demo boundary; other backends and general host portability are not established.
