# Core

Keep input construction and diagnostic repair in `generation.deal`. `source-repair.deal` applies only bounded, unique, disjoint exact edits against a digest-bound source pair; never treat it as a semantic compiler editor. Recheck the complete pair after edits. Repeated replies are feedback, never terminal. Repair only with targeted exact patches and code/language-specific bounded diagnostic context; never duplicate the base source or retain a full-rewrite repair branch. Emit explicit initial/repair operation metadata. Invalid initial envelopes recover within the same request before a patch base exists; failed patches retain the last valid base. Generation has no attempt ceiling and ends on acceptance or explicit cancellation. Retry classified provider/transport failures without disguising them as source errors. Repairs are normal for complex cases; minimize changed scope, latency and behavioral regression rather than demanding zero repairs. Keep invariant guidance/contracts before variable intent/context for provider prefix reuse. Backends implement the imported `host/*.d.deal` APIs. Rejected deterministic source is recorded as a policy defect and falls through to source generation; do not pass it off as accepted.

Keep catalogue offer/lowering in the consuming app's compiled DEAL policy, never in this library. Core owns fallback, recovery and checker admission. Generic typed question/answer validation belongs at the transport boundary; domain relations belong in app lowering. `source-literals.deal` owns DEAL literal escaping. The policy-data import provides shape conversion, Unicode lowercase and UTF-16 units, not domain decisions. Preserve noninterfering unified observation and propagate host operational failures. Observe patch boundaries through the trusted observer without persisting patch/source content in routine metrics. Do not add arbitrary call, repetition or malformed-envelope terminal conditions.

Catch only expected input/JSON shape rejection; keep awaited host primitives outside shape catches and propagate operational failures. Invalid JSON is explicitly `INVALID_JSON`, not every parse mechanism failure.

Keep envelope validation in `candidate-check.deal`; call the native checker with two validated source strings. Native candidate rejection supplies diagnostics; unexpected compiler/resource failures propagate without repair.

Use DEAL 1.3 semantics and explicit target types for table reads; keyword wire fields use typed string-key table indexing. Do not restore superseded compiler workarounds or invent alternate provider fields. Keep prompt assembly in `generation-guidance.deal`; portable composition prose and authored examples belong in `ui/`. Generated guidance contains those asset texts and pack AST facts, including typed children; build tooling must not select example arguments or composition rules. The example's `host/sample` is fixture-only, not an application capability. Keep examples compiler/runtime-checked, including explicit-read/success/failure/retry and local comparison transitions.

`repair-guidance.deal` adds bounded source windows and pack-derived component facts to targeted exact repair. It has no edit authority and must not swallow operational shape-parser failures. Route syntax advice by structured diagnostic code, source language and the offending source line; a generic parser message must not imply unrelated equality/import edits. Keep diagnostic-specific instructions aligned with compiler rejection codes; the complete candidate remains subject to ordinary admission.

Treat those declarations as canonical signatures and `host/check-result.json` as the canonical checker-result wire schema. Keep native replies, core field reads and generated binding metadata aligned with them.

Keep trusted observation stages registered in logging.deal so discovery stages survive normalization and remain identifiable through the public observation stream. Restrict the core's host imports to trusted orchestration. Generation returns checked candidate identities; hosts validate disclosed context and catalog revision before activation.

Keep `ui/generation-guidance.md` aligned with accepted DEAL syntax, Deal UI semantics and the renderer pack. Distinguish JSON envelope escapes from DEAL string syntax: Unicode text must reach source as literal characters, not unsupported JSON-style Unicode escapes. Do not rewrite accepted source or filter rendered text to repair generation mistakes. Include the exact closed source envelope, host module filenames, exported state/action types, literal pack import, conditional syntax and payload-bearing event examples; honor pack defaults in generated call facts; examples must not contradict component contracts. Preserve intent-driven workflow generation and immutable state updates. Generated tools must follow capability argument semantics and prerequisite reads, resolving IDs from actual returned records; pending or invalid data must not appear as zero-price success. Keep catalogue and generation guidance task-facing: no raw error codes or engineering taxonomy on ordinary screens. Apply task-first presentation to every consumer, not just Organizer: controls and results precede explanations; Inspect owns provenance and diagnostics; native consent owns disclosure. Do not instruct generated tools to repeat shell headings, safety paragraphs or captured context. Verify guidance changes with fresh generated output, not only the checked syntax example; functional correctness is not visual acceptance. Pending effects must show progress, prevent conflicting submission and restore controls on completion/failure; engineering diagnostics remain in the unified logger.
