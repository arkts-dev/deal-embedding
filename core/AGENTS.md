# Core

Keep input construction and diagnostic repair in `generation.deal`. `source-repair.deal` applies only unique, disjoint exact edits against a digest-bound source pair, without edit-count/size ceilings; never treat it as a semantic compiler editor. Distinguish no-match from multiple-match rejection with zero-based edit index, target file and overlapping match counts (including the other file), without applying or relocating edits. On ambiguity include all occurrence line locations and literal numbered context for the first eight occurrences; additional ranges remain readable through read_file. Preview limits never limit accepted edits. `source-agent.deal` owns compact submission, explicit full-source fallback and the two-file staged workspace. The trusted composer emits the initial pair atomically without provider execution; malformed plans leave both files absent. Once materialized, return exact expanded bytes on rejection and use read_file/edit_sources/check_sources only, never reassemble behind exact edits. Initial write_file is available only after explicit source_fallback. The model supplies task computations; composition must not introduce app-specific solvers or infer missing requirements. Host binds edits to the current revision; the model never copies digests or boundary tokens. Reject file overwrites, invalid tools and nonunique edits without changing the workspace. Provider adapters transport native assistant/tool messages, not executable source envelopes. Core emits initialWrites from staged-file state; allow paired independent initial writes only while both files are absent, preflight the whole batch before staging, and disable batching after either file exists. Preserve single-write recovery. read_file supports inclusive 1-based ranges with literal numbered line records and nullable bounds for full reads; reject invalid ranges without clipping or changing sources. Keep full-file reads available and line numbers outside exact edit text. Recheck the complete pair after edits. Repeated replies are feedback, never terminal. Repair only with targeted exact patches and code/language-specific bounded diagnostic context; never duplicate the base source or retain a full-rewrite repair branch. Emit explicit initial/repair operation metadata. Invalid native calls recover within the same request before a patch base exists; failed patches retain the last valid base. Generation has no attempt ceiling and ends on acceptance or explicit cancellation. Retry classified provider/transport failures without disguising them as source errors. Repairs are normal for complex cases; minimize changed scope, latency and behavioral regression rather than demanding zero repairs. Keep invariant guidance/contracts before variable intent/context for provider prefix reuse. Backends implement the imported `host/*.d.deal` APIs. Rejected deterministic source is recorded as a policy defect and falls through to source generation; do not pass it off as accepted.

Keep catalogue offer/lowering in the consuming app's compiled DEAL policy, never in this library. Core owns fallback, recovery and checker admission. Generic typed question/answer validation belongs at the transport boundary; domain relations belong in app lowering. `source-literals.deal` owns DEAL literal escaping. The policy-data import provides shape conversion, Unicode lowercase and UTF-16 units, not domain decisions. Preserve noninterfering unified observation and propagate host operational failures. Observe patch boundaries through the trusted observer without persisting patch/source content in routine metrics. Do not add arbitrary call, repetition or malformed-envelope terminal conditions.

Catch only expected input/JSON shape rejection; keep awaited host primitives outside shape catches and propagate operational failures. Invalid JSON is explicitly `INVALID_JSON`, not every parse mechanism failure.

Keep native tool execution in `source-agent.deal` and internal pair validation in `candidate-check.deal`; host-serialized internal JSON is an ABI, not model-authored output. Call the native checker with two validated source strings. Native candidate rejection supplies diagnostics; unexpected compiler/resource failures propagate without repair.

Use DEAL 1.4 semantics and explicit target types for table reads; keyword wire fields use typed string-key table indexing. Do not restore superseded compiler workarounds or invent alternate provider fields. Keep prompt assembly in `generation-guidance.deal`; portable composition prose and authored examples belong in `ui/`. The example's `host/sample` is fixture-only, not an application capability. Keep examples compiler/runtime-checked, including explicit-read/success/failure/retry and local comparison transitions.

`repair-guidance.deal` lists every diagnostic location and merges nearby source windows per file, emitting each preview line once. Bound only the context preview, explicitly label omitted context and keep it available through read_file; deduplicate repeated advice without dropping diagnostic locations. It adds pack-derived component facts to targeted exact repair. It has no edit authority and must not swallow operational shape-parser failures. Label source excerpts with the actual diagnostic filename, patch target and line numbers (numbers are not source). Route syntax advice by structured diagnostic code, source language and the offending source line; a generic parser message must not imply unrelated equality/import edits. Extract reserved identifiers mechanically from the compiler lexer into build-derived guidance. For E1007 report a reserved offending token only when it matches at the diagnostic column with an identifier boundary. Keep model repair instructions on edit_sources, never model-supplied digests. Keep diagnostic-specific instructions aligned with compiler rejection codes; the complete candidate remains subject to ordinary admission.
