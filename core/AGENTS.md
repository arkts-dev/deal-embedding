# Core

Keep input construction and diagnostic repair in `generation.deal`. `source-repair.deal` applies only bounded, unique, disjoint exact edits against a digest-bound source pair; never treat it as a semantic compiler editor. Recheck the complete pair after edits and reject repeated model responses. Keep full repair as the default until a measured comparison supports promotion. Backends implement the imported `host/*.d.deal` APIs. Rejected template source is a deterministic defect, not a source-generation repair opportunity; return its checker diagnostics without further model calls.

Keep catalogue offer/lowering in the consuming app's compiled DEAL policy, never in this library. Core owns fallback, bounded repair and checker admission. Generic typed question/answer validation belongs at the transport boundary; domain relations belong in app lowering. `source-literals.deal` owns DEAL literal escaping. The policy-data import provides shape conversion, Unicode lowercase and UTF-16 units, not domain decisions. Preserve noninterfering unified observation and propagate host operational failures.

Catch only expected input/JSON shape rejection; keep awaited host primitives outside shape catches and propagate operational failures. Invalid JSON is explicitly `INVALID_JSON`, not every parse mechanism failure.

Keep envelope validation in `candidate-check.deal`; call the native checker with two validated source strings. Native candidate rejection supplies diagnostics; unexpected compiler/resource failures propagate without repair.

Keep composition and prompt formatting in `generation-guidance.deal`. Generated guidance contains asset text, pack AST facts and the authored `generation-example` source pair only; build tooling must not select example arguments or composition rules. The example's `host/sample` is fixture-only, not an application capability. Keep it compiler-checked with an explicit-read/success/failure/retry regression.

`repair-guidance.deal` adds bounded source windows and pack-derived component facts to full-source repair only. It has no edit authority and must not swallow operational shape-parser failures. Keep diagnostic-specific instructions aligned with compiler rejection codes; the complete candidate remains subject to ordinary admission.

Treat those declarations as canonical signatures and `host/check-result.json` as the canonical checker-result wire schema. Keep native replies, core field reads and generated binding metadata aligned with them.

Keep trusted observation stages registered in logging.deal so discovery stages survive normalization and remain identifiable through the public observation stream. Restrict the core's host imports to trusted orchestration. Generation returns checked candidate identities; hosts validate disclosed context and catalog revision before activation.

Keep `generation-guidance.md` aligned with accepted DEAL syntax, Deal UI semantics and the renderer pack. Distinguish JSON envelope escapes from DEAL string syntax: Unicode text must reach source as literal characters, not unsupported JSON-style Unicode escapes. Do not rewrite accepted source or filter rendered text to repair generation mistakes. Include the exact closed source envelope, host module filenames, exported state/action types, literal pack import, conditional syntax and payload-bearing event examples; honor pack defaults in generated call facts; examples must not contradict component contracts. Preserve intent-driven workflow generation and immutable state updates. Generated tools must follow capability argument semantics and prerequisite reads, resolving IDs from actual returned records; pending or invalid data must not appear as zero-price success. Keep catalogue and generation guidance task-facing: no raw error codes or engineering taxonomy on ordinary screens. Apply task-first presentation to every consumer, not just Organizer: controls and results precede explanations; Inspect owns provenance and diagnostics; native consent owns disclosure. Do not instruct generated tools to repeat shell headings, safety paragraphs or captured context. Verify guidance changes with fresh generated output, not only the checked syntax example; functional correctness is not visual acceptance. Pending effects must show progress, prevent conflicting submission and restore controls on completion/failure; engineering diagnostics remain in the unified logger.
