# Rendering

[spec-v0.8](../../../docs/spec-v0.8.md) is the sole embedding authority; current renderer behavior, pack defaults and examples are subordinate.

Render checked trees and deliver typed input through compiled actions. Generate renderer metadata from the reconciled pack; preserve keys, nominal payloads, numeric values and Unicode. Do not infer domain conclusions or rewrite accepted text. Numeric presentation follows the shared `decimals`/`minimumDigits` field rule: automatic decimals use the shortest round-tripping decimal, fixed decimals round half away from zero, the integer part pads with leading zeros, and affixes are added unchanged.

Native rendering owns layout, drawing and presentation resources, not business state, admission, recovery or computational clocks. Separate rendering/publication from execution progress. Diagnostic hooks and observation failures must not change application outcomes.

`Image` resolves its `src` through the one permitted transport rule (`TransportPolicy`): HTTPS, or HTTP only on loopback, with no embedded credentials, no fragment, no redirect, no request body and no cache. The scheme and host are case-insensitive. Applying the shared rule to tree-authored content is deliberate: a tree may reach an HTTPS origin or the device's own loopback and never falls back to a `file`, `content` or `data` scheme. Loopback HTTP is the host's grant, not the tree's: the renderer asks the platform's cleartext policy (`NetworkSecurityPolicy.isCleartextTrafficPermitted`) for that host before it connects, so a host that denies cleartext to loopback through its network security configuration gets `IMAGE_TRANSPORT` before any request; Android 17 and later implicitly permit cleartext to loopback unless the host configures otherwise, and the renderer never switches transport to work around a host configuration. Its transfer, decode and picture are bounded by the host's `ExecutionLimits` - four bytes per pixel, one lane share of the heap bound per transfer and per decoded picture, so concurrent loads peak at about half the heap bound, and the host evaluation bound as the transfer deadline; a displayed picture is one such share whose reference is dropped when its node replaces it or leaves - not recycled, because a frame recorded before the replacement may still draw it - and native exhaustion inside a load is a classified failure. Blocking transfer and decode run on the renderer's own lane. A failure code is logged when the node enters its failure state, which shows that state explicitly with its `alt` text still accessible. The host's configured bounds reach every hosted surface through `LocalExecutionLimits`; a caller of the public `DealRenderer` outside a hosted surface gets the default `ExecutionLimits`.

Host prerequisite, deliberately not an AAR declaration: an application that renders images declares `android.permission.INTERNET` in its own manifest. Without it every resource fails as `IMAGE_UNAVAILABLE`. Loopback `http` additionally needs the cleartext grant described above, so a host that denies cleartext to loopback through its network security configuration gets `IMAGE_TRANSPORT` before any request. Neither is worked around by switching transport.
